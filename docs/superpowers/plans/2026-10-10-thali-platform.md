# Thali Food Delivery Platform — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the working MERN microservices food-delivery platform described in the PRD — consumer, restaurant, partner and admin experiences with multi-restaurant checkout, payments, delivery and notifications — runnable via Docker Compose in demo mode with sandbox-ready provider adapters.

**Architecture:** npm-workspaces monorepo: 3 shared packages (`contracts`, `pricing`, `service-kit`), 6 domain services + gateway (Express 5/TS, Mongoose 8, one DB per service on a Mongo replica set), Redis Streams + transactional outbox for events, Mongo-backed leader-locked sweepers for timers, one React/Vite SPA with four role areas, SSE realtime with polling fallback.

**Tech Stack:** Node 22, TypeScript 5.9.3, Express 5.3.0, Mongoose 8.24.5, ioredis 5.11.1, Zod 4.6.5, zod-to-openapi 8.5.0, jose 6.2.12, argon2 0.45.1, otplib 12.0.1, React 19.3.0, Vite 7.3.7, React Router 7.18.4, TanStack Query 5.104.1, Tailwind 4.3.3, Leaflet 1.9.4, Vitest 3.2.7, Playwright 1.64.0, Docker Compose.

**Spec:** `docs/01-PRD.md` (requirements), `docs/02-HLD.md` (architecture), `docs/03-LLD.md` (binding contracts: models, enums, state machines, events, APIs, algorithms), `docs/04-ADR.md` (decisions). Source brief: `context.md`.

**Plan-format note:** at this scale (≈40k LOC) full code cannot be inlined per step. Instead every task names exact files, the LLD sections that are its contract, exact interfaces it produces/consumes, and the exact test cases (name + assertion) to write first. The LLD is binding — implementers read the referenced sections, not paraphrases.

## Global Constraints

- Node 22 LTS; ESM only (`"type":"module"`, `module`/`moduleResolution: NodeNext`); TypeScript `strict: true`.
- All dependency versions exact-pinned (no `^`/`~`), versions per LLD §0. Do **not** add dependencies or edit any `package.json`/`package-lock.json` outside Task 1; if a dependency is truly missing, report `NEEDS_CONTEXT`.
- Money = integer paise (`*Paise`), rates = basis points (`*Bps`); no floats in money math.
- Timestamps stored UTC; display timezone `Asia/Kolkata`.
- Every API under `/api/v1`; error envelope `{ error: { code, message, details?, requestId } }` (LLD §1.2); codes from `@thali/contracts` `ErrorCode`.
- A service reads/writes only its own database `thali_<service>`; cross-service via `/internal/*` HTTP with service token or events (LLD §1.6, §9).
- State changes that emit events use the outbox in the same Mongo transaction; event handlers are idempotent via inbox.
- Every route registered in the service's OpenAPI registry (request/response schemas, security, errors). Swagger at `/docs`, spec at `/openapi.json` per service; aggregated at gateway `/api/docs`.
- Validation with Zod at every boundary; `requireAuth`/ownership on every non-public route; internal routes use `requireInternal`.
- `APP_MODE=demo|sandbox|production`; production refuses mock providers / demo flags at startup.
- Tests use real MongoDB replica set + Redis from `docker-compose.infra.yml` (`mongodb://localhost:27017/?replicaSet=rs0&directConnection=true`, `redis://localhost:6379`) with unique DB names and a unique `EVENT_STREAM_PREFIX`/Redis key prefix per test file — tests must be safe to run in parallel with other services' tests.
- Implementers do **not** create git commits; the controller commits after review. Do not run `git add`/`git commit`/`git stash`/`git checkout`.
- No placeholder UI: every button calls a real API; every screen handles loading / empty / error / forbidden / session-expired states.
- Demo data and mock providers must be visibly labeled (`isDemo`, `estimateSource`, `simulated`, mode banner).

## Review Focus

1. **Opening hours across midnight & IST day boundary** — hours like `18:00–02:00` and a UTC time that is a different weekday in IST must compute open/closed correctly. Test: Task 8 `open-status.test.ts`.
2. **Phone input variants** — `+91 98765 43210`, `09876543210`, `9876543210`, `919876543210` normalize to `+919876543210`; landline/short/alpha rejected. Test: Task 2 `phone.test.ts`.
3. **Webhook raw body through gateway + express** — signature must be computed over the exact raw bytes; JSON re-serialization by any layer breaks it. Test: Task 10 `webhook.int.test.ts` (whitespace-variant body) and Task 14 `proxy.test.ts` (byte-identical passthrough).
4. **SSE through the gateway proxy** — no buffering/compression; heartbeat arrives within 25 s; client falls back to polling on disconnect. Test: Task 14 `sse-proxy.test.ts`; Task 16 `useRealtime.test.ts`.
5. **Same item, different customizations** — two cart lines; selection min/max and unavailable option rejected server-side at add and at checkout. Test: Task 11 `cart.int.test.ts`; Task 9 `quote.int.test.ts`.
